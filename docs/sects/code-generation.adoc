This document covers Hydra's code generation system, which transforms DSL definitions into native language implementations across multiple target languages.

== Overview

Hydra's code generation is one of its most powerful features, allowing the kernel to be defined once in Haskell DSL and then automatically translated to multiple target languages. This ensures consistency across implementations while enabling native performance and idioms in each language.

=== Generated vs. Hand-Written Code

* **Generated Code**: Type definitions, basic functions, standard library primitives
* **Hand-Written Code**: Language-specific optimizations, native integrations, platform-specific code

== Working with Generated Code

=== Interactive Code Generation

The most flexible approach uses GHCi for interactive code generation:

[source,bash]
----
# Start interactive session
pixi run -e haskell stack-ghci

# In GHCi, load the code generator
:l Hydra.Codegen

# Generate Haskell code
writeHaskell "src/gen-main/haskell" mainModules
writeHaskell "src/gen-test/haskell" testModules

# Generate Java code
writeJava "../hydra-java/src/gen-main/java" mainModules
writeJava "../hydra-java/src/gen-test/java" testModules
----

=== Automated Code Generation

Use pixi tasks for automated generation:

[source,bash]
----
# Generate all Haskell code from DSL definitions
pixi run -e haskell generate-haskell

# Generate all Java code from DSL definitions
pixi run -e haskell generate-java

# Build after generation to verify correctness
pixi run -e haskell stack-build
pixi run -e java gradle-build
----

=== Verification After Generation

Always verify that generated code compiles and passes tests:

[source,bash]
----
# Test generated Haskell code
pixi run -e haskell stack-test

# Test generated Java code
pixi run -e java gradle test

# Run integration tests
pixi run build-all
----

=== Module Registration

Generated modules must be registered in the appropriate tier registry:

[source,haskell]
----
-- In Hydra/Sources/Tier3/All.hs
module Hydra.Sources.Tier3.All where

-- Import your new modules
import qualified Hydra.Sources.Tier3.YourNewModule as YourNewModule

-- Add to the module list
allModules :: [Module]
allModules = [
  -- ... existing modules
  YourNewModule.module_,
  -- ... more modules
  ]
----

== Language-Specific Generation

=== Haskell Code Generation

Generates native Haskell modules with proper imports and exports:

[source,bash]
----
# Generate main Haskell modules
pixi run -e haskell stack-ghci
:l Hydra.Codegen
writeHaskell "src/gen-main/haskell" mainModules

# Generated structure
src/gen-main/haskell/
├── Hydra/
│   ├── Core.hs
│   ├── Graph.hs
│   └── Compute.hs

Generated Haskell features:
* Type-safe data constructors
* Pattern matching functions
* Proper module hierarchies
* Haddock documentation comments

== Customizing Code Generation

=== Adding New Language Support

To add support for a new target language:

1. **Define Language Constraints**:
[source,haskell]
----
-- In Hydra/Sources/Tier3/Ext/YourLanguage/Language.hs
yourLanguageConstraints :: LanguageConstraints
yourLanguageConstraints = LanguageConstraints {
  -- Define supported constructs
  }
----
+
2. **Create Language Coder**:
[source,haskell]
----
-- In Hydra/Ext/YourLanguage/Coder.hs
codeType :: Type -> Flow (Context) YourLanguageSyntax
codeTerm :: Term -> Flow (Context) YourLanguageSyntax
----
+
3. **Implement Serializer**:
[source,haskell]
----
-- In Hydra/Ext/YourLanguage/Serializer.hs
serializeExpression :: YourLanguageSyntax -> String
----
+
4. **Register Generation Function**:
[source,haskell]
----
writeYourLanguage :: FilePath -> [Module] -> IO ()
writeYourLanguage = generateSources yourLanguageConstraints codeType codeTerm serializeExpression
----

=== Customizing Existing Generators

Modify generation behavior by updating:

* **Language constraints**: Change supported language features
* **Coders**: Modify how Hydra constructs map to target language
* **Serializers**: Change output formatting and style
* **Templates**: Modify file headers, imports, and boilerplate

== Development Workflow

=== Iterative Development

1. **Modify DSL sources** in `Hydra/Sources/`
2. **Regenerate code** with pixi tasks
3. **Build and test** in target languages
4. **Debug issues** by examining generated code
5. **Refine DSL sources** and repeat

[source,bash]
----
# Development cycle
pixi run -e haskell generate-haskell
pixi run -e haskell stack-build
pixi run -e haskell stack-test

# If tests fail, examine generated code
pixi run -e haskell haskell-modules
pixi run -e haskell stack-ghci
-- :browse Hydra.YourModule
----

=== Debugging Generated Code

Common debugging approaches:

[source,bash]
----
# Compare generated code before/after changes
git diff src/gen-main/

# Interactive exploration
pixi run -e haskell stack-ghci
:l Hydra.YourGeneratedModule
:browse Hydra.YourGeneratedModule
:type someGeneratedFunction

# Find specific functions
pixi run -e haskell haskell-functions | grep "yourFunction"
----

== Code Generation Best Practices

=== DSL Design Guidelines

1. **Keep types simple**: Complex nested types are harder to generate cleanly
2. **Use consistent naming**: Names should translate well across languages
3. **Document thoroughly**: Comments in DSL become documentation in generated code
4. **Consider target languages**: Some constructs don't translate to all languages

=== Generation Quality

1. **Always regenerate after changes**: Don't edit generated code directly
2. **Test all target languages**: Ensure generation works for all supported languages
3. **Verify compilation**: Generated code must compile without warnings
4. **Check performance**: Generated code should be reasonably efficient

=== Version Control

1. **Commit generated code**: Include generated code in version control
2. **Review generated changes**: Always review diffs in generated code
3. **Coordinate updates**: Update all language implementations together
4. **Tag releases**: Ensure generated code matches tagged versions

== Advanced Topics

=== Custom Code Templates

For specialized generation needs, create custom templates:

[source,haskell]
----
-- Custom template for specific language features
customTemplate :: TemplateConfig -> String
customTemplate config = [str|
  // Generated by Hydra #{version}
  // Custom template for #{languageName}

  #{generatedContent}
|]
----

=== Conditional Generation

Generate different code based on target language capabilities:

[source,haskell]
----
generateConditionally :: LanguageConstraints -> Type -> Flow s Expression
generateConditionally constraints typ
  | supportsGenerics constraints = generateGenericVersion typ
  | otherwise = generateNonGenericVersion typ
----

=== Cross-Language Testing

Ensure behavioral parity across generated implementations:

[source,bash]
----
# Generate test data in one language
pixi run -e haskell run-example-graphson

# Verify same results in other languages
pixi run -e java gradle run --args="verify-graphson"
----

== Troubleshooting

=== Common Issues

==== Generation Fails

**Symptoms**: Code generation throws errors or produces invalid code.

**Solutions**:
1. Check DSL syntax in source definitions
2. Verify all imports are available
3. Ensure proper tier dependencies
4. Review language constraints compatibility

[source,bash]
----
# Debug generation issues
pixi run -e haskell stack-ghci
:set -XOverloadedStrings
:l Hydra.Codegen
-- Try individual generation functions
----

==== Generated Code Won't Compile

**Symptoms**: Generated code has syntax errors or missing imports.

**Solutions**:
1. Check coder implementation for target language
2. Verify serializer produces valid syntax
3. Update language constraints if needed
4. Review import generation logic

==== Performance Issues

**Symptoms**: Generated code is slower than expected.

**Solutions**:
1. Profile generated code execution
2. Optimize coder algorithms
3. Use language-specific optimizations
4. Consider hand-written alternatives for hot paths
