== Outstanding Issues Requiring Attention

=== Java Build Issues

*Problem*: Missing generated Java classes in `hydra.lib.strings` package

* Classes like `Length`, `Cat`, `SplitOn`, `ToLower`, `ToUpper` are imported but don't exist
* These appear to be generated by the Haskell build process
* The conda build isolation prevents access to generated files

*Recommended Fix*:

. Generate missing Java classes before conda build
. Or include pre-generated classes in repository
. Or modify build order to build Haskell first

=== Haskell Linking Issues

*Problem*: GHC linking fails with missing `posix_spawn_file_actions_addchdir_np`

* This is a glibc compatibility issue between conda environment and Stack/GHC
* Stack's GHC expects newer glibc features not available in conda's glibc

*Recommended Fixes*:

. Use `ghcup-*` tasks instead of `stack-*` tasks
. Configure Stack to use system GHC: `stack --system-ghc`
. Update conda glibc package if possible
. Consider using Docker for Haskell builds

=== Multi-package Dependency Issues

*Problem*: hydra-ext conda build can't find hydra-haskell dependency

* Conda builds packages in isolation
* hydra-ext requires hydra-haskell to be built first

*Recommended Fix*:

. Build packages in correct dependency order
. Use conda build features for multi-package builds
. Or build as single combined package

=== Scala Build Issues

*Problem*: SBT version compatibility with conda-provided Java

* ClassCastException in SBT launcher
* Java 11 vs SBT version mismatch

*Recommended Fix*:

. Update SBT version in conda recipe
. Or pin Java version more specifically
. Or use alternative Scala build tool

=== GraphSON Generation

*Problem*: runhaskell not available in conda environment

* GraphSON generation tasks fail
* However, pre-generated files already exist

*Recommended Fix*:

. Add runhaskell to conda dependencies
. Or use stack exec -- runhaskell
. Or document that files are pre-generated
